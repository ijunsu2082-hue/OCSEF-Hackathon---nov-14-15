# Location ETL

Run from the repository root with project dependencies installed.

```powershell
npx tsx research/etl/cli.ts collect --lat 34.0522 --lon -118.2437 --radius 100 --respondent CISO
npx tsx research/etl/cli.ts collect --lat 33.7538 --lon -118.0111 --radius 100 --caiso
npx tsx research/etl/cli.ts verify <location-id> <revision>
npx tsx research/etl/cli.ts replay <location-id> <revision>
npx tsx research/etl/cli.ts coverage --strict
npx tsx research/etl/cli.ts backfill weather 34.0522 -118.2437 2024-01-01 2024-01-03
npx tsx research/etl/cli.ts assets hifld-transmission 33.7538 -118.0111 100
npx tsx research/etl/cli.ts replay-assets <asset-manifest-path>
npx tsx research/etl/cli.ts load-assets <asset-manifest-path> [additional-manifest-path]
npx tsx research/etl/cli.ts audit-substations public/layers/substations.geojson <hifld-manifest> <crosswalk.json>
npx tsx research/etl/cli.ts collect --lat 33.7538 --lon -118.0111 --radius 100 --caiso --oasis-node TH_SP15_GEN-APND
npx tsx research/etl/cli.ts backfill eia930 CISO <EIA930_BALANCE_file.csv> [--url <source-url>]
npx tsx research/etl/cli.ts reconcile <location-id> [report-revision]
npx tsx research/etl/cli.ts crosswalk-candidates public/layers/substations.geojson <hifld-substations-manifest> [--max-metres 300]
npx tsx research/etl/cli.ts ratings generate <weather-snapshot-id> <site-key> <year> [--utc-offset -8]
npx tsx research/etl/cli.ts ratings compare <generated.csv> <reference.csv>
npx tsx research/etl/cli.ts ratings parity public/layers/line_rating_2025_westminster_hs.csv
npx tsx research/etl/cli.ts operator-import <envelope.json> [readings.csv]
npx tsx research/etl/cli.ts osm-regen pin --pbf <file> --url <url> --headers <curl-headers> [--final-url <url>] [--md5 <md5>] [--out <manifest>]
npx tsx research/etl/cli.ts osm-regen regen [--pbf <file>] [--manifest <file>] [--committed public/layers] [--out <dir>]
npx tsx research/etl/cli.ts eia860 pin --file <zip> --url <url> --headers <curl-headers> [--period <p>] [--out <manifest>]
npx tsx research/etl/cli.ts eia860 regen [--zip <file>] [--manifest <file>] [--committed <plants.geojson>] [--out-dir <dir>] [--loaded <loaded-assets.json>] [--m860 <file> --m860-manifest <file>]
```

A malformed or missing argument prints a one-line error or usage message to stderr and exits 1. Commands that return a result print it as one JSON line on stdout (`reconcile` prints the persisted canonical record). `osm-regen` and `eia860` are loaded on demand, so a fault in those modules cannot break any other command; their output and defaults are described in `docs/OSM-REGENERATION-DIFF.md` and `docs/EIA860-REGENERATION-DIFF.md`. Neither writes under `public/`. `package.json` runs the suites: `npm run test:etl` (every `research/etl`, `lib` and `components` `*.test.ts`), `npm run verify:owner` (each `scripts/verify-owner-*.ts`, stopping at the first failure) and `npm run test:service` (pytest on `test_service.py`; needs Python 3.10 or later with `requirements-dev.txt` installed, chosen with `PYTHON=<interpreter>`).

Collection prints the report to stdout and, as its last stderr line, the location ID and pinned revision behind a fixed sentinel: `@@MAPERGY_RESULT@@ {"location":"<location-id>","revision":"<revision>"}`. Other stderr lines (Node warnings, retry notices) may precede it; readers should take the last sentinel line rather than the last line. The FastAPI service does this and still accepts the older unprefixed JSON line. `--caiso` (no value, at most once) adds the CAISO feeds to the query; it changes the location ID because the query is part of it. `--oasis-node <NODE>` (at most once) adds the two CAISO OASIS LMP feeds for that pricing node (see "CAISO OASIS nodal prices"). The node joins the query, and so the location ID, only when it is set; queries without it keep their existing IDs. The FastAPI service passes it from a location's `oasis_node`. The Next.js JSON endpoint accepts `?revision=<revision>`. Collection stores final source responses locally before parsing and records rejected captures separately. Sources use their configured refresh intervals. Failed attempts retain the previous capture if its checksum and parser replay succeed. Such a feed has status `fallback`, `issue_code: "fetch_failed"` and `freshness` (`fresh`, `stale` or `unknown`), the measured freshness of the replayed capture; its gap is `stale` unless that capture is still fresh, in which case it is `requires_review`, and the gap detail starts with `fetch_failed:`. A failed fetch with no prior capture is `unavailable` with the same `issue_code` and a `no_source` gap. Reports carry `schema: "mapergy.location-report/2"` (reports written before the rename carry `"gridsentinel.location-report/2"` and an evidence bundle with `gridsentinel.evidence/1`; they still verify and replay under those ids); a report without it predates the marker and replays under the rules it was written with (an all-unavailable one is not mistaken for a pre-observation-time legacy report).

Asset collection accepts `eia-atlas-plants`, `hifld-substations`, and `hifld-transmission`. It captures the provider's radius-filtered ID list, fetches geometry and attributes by ID, and verifies one returned feature per listed ID before publishing. GeoJSON contains complete intersecting features. Segment clipping and mileage derivation belong to downstream processing. Replay uses only saved response bytes. These manifests are separate from location-report backups.

`load-assets` replays saved manifests for one coordinate and radius, normalizes registered fields, and publishes an immutable JSON asset revision. It retains separate provider datasets, field and geometry citations, and counts of missing fields. A failed transform leaves the previous revision available. Plant generation and retirement metrics still require the EIA workbooks.

Two routes serve loaded assets. `GET /api/location-report/<location-id>/assets` serves only the inventory revision the report was bound to; use it for report citations. `?report=<report-revision>` selects a pinned report revision and returns immutable cache headers. Without `?report=` it uses the latest report and sends `no-store`. `?revision=<asset-revision>` asserts the bound revision and returns `409` when it differs. It never falls back to the latest loaded inventory. Responses carry `X-Report-Revision` and `X-Asset-Revision`. `GET /api/location-assets/<inventory-id>?revision=<asset-revision>` is inventory-only, with no report involved. The inventory id is `locationId({center, radius_miles})`, without respondent or CAISO. This is the id the scan page computes and receives over the websocket, and it backs the page's "Open pinned inventory JSON" link. Malformed ids or revisions return `400` and unknown revisions return `404`. With `?revision=` the response is cached as immutable; without it the route serves the latest revision with `no-store`. Every success carries `X-Asset-Revision`.

Binding: each live run binds the report to the verified latest loaded inventory for its center and radius. Offline replay reuses the binding the replayed report recorded. Publishing a new inventory does not touch existing report revisions; the next live run rebinds and writes a new report revision. The binding is `null` when no inventory is loaded. It is also `null` when the latest inventory fails to read: a checksum mismatch, malformed JSON, or an invalid `latest.json`. In that case the live build still succeeds, writes `quarantine/assets/<inventory-id>/<timestamp>.json` (inventory, path, `detectedAt`, issue), and prints one `Mapergy: asset inventory ... rejected (...)` warning to stderr. That line is not a result-sentinel line. Once the inventory is repaired or republished, the next live run rebinds.

The FastAPI service schedules inventory separately from telemetry. Set `ETL_ASSET_LOCATIONS` to a JSON array to opt in; each item needs `lat` and `lon`, with optional `radius` (default `100`) and `sources` (default all three supported asset sources). Keep each coordinate/radius scope unique and each source listed once. Inventory workers collect each source, then publish through `load-assets`; failed attempts retry after 60 seconds and do not replace the last loaded snapshot. Successful cycles wait 86,400 seconds by default. `ETL_ASSET_REFRESH_SECONDS` and `ETL_ASSET_RETRY_SECONDS` set those intervals; `ETL_ASSET_CONCURRENCY` caps simultaneous inventory locations (default `2`). All interval and concurrency values must be positive. Empty `ETL_ASSET_LOCATIONS` keeps inventory scheduling off.

Telemetry runs one task per `ETL_LOCATIONS` entry (`lat`, `lon`, optional `radius`, `respondent`, `oasis_node`, and `caiso`, default `false`; `caiso: true` passes `--caiso` and `oasis_node` passes `--oasis-node`, validated against `^[A-Z0-9_\-.]{3,64}$`). Each location keeps its own fixed-rate cadence: `ETL_TELEMETRY_INTERVAL_SECONDS` if set, otherwise 300 seconds when `caiso` is true or `oasis_node` is set (CAISO telemetry and OASIS RTM intervals are 5-minute) and 600 seconds otherwise (NWS observations are 10-minutely). Ticks fall on start + k × interval; ticks missed while the process was stalled are skipped, not replayed. A run never overlaps itself: if it is still running at the next tick, that tick is skipped and logged. Failures are logged per location and retried at the next tick. `ETL_TELEMETRY_CONCURRENCY` (default `4`) caps simultaneous collector processes across all locations, so a slow location delays no other location's tick. Both values must be positive. The CLI's per-feed freshness reuse still applies inside each run.

```powershell
$env:ETL_ASSET_LOCATIONS = '[{"lat":33.7538,"lon":-118.0111,"radius":100,"sources":["hifld-substations","hifld-transmission"]}]'
$env:ETL_ASSET_REFRESH_SECONDS = '86400'
$env:ETL_ASSET_RETRY_SECONDS = '60'
$env:ETL_ASSET_CONCURRENCY = '2'
```

Substation crosswalks are reviewed JSON arrays with `osm` (such as `node/123`), `hifld` (such as `hifld-substations:456`), `snapshot` (the HIFLD feature's citation snapshot), and `evidence` (the record establishing common identity). Audit replays the HIFLD captures, compares published names and operators where both exist, and lists unpaired records. Ownership and maximum voltage remain separate HIFLD fields. Use captures covering the same study area when comparing totals.

Set `EIA_API_KEY` for EIA hourly telemetry and `NWS_USER_AGENT` to a contact-bearing user agent. Passing a respondent specifies the reporting authority for the query. The location center alone does not establish the respondent.

## Backup and restore

Set `ETL_BACKUP_KEY` to a securely generated 32-byte hex key. Store it separately from encrypted backup files. Use an independently mounted destination for backup files. Archives are AES-256-GCM. Restore checks that the envelope has a 12-byte nonce and a full 16-byte authentication tag before it decrypts, and the decipher is pinned to `authTagLength: 16`, so a truncated tag is rejected (Node otherwise accepts tags as short as 4 bytes, DEP0182). Asset restore also rejects any manifest `source` that is not 1 to 64 characters of `[a-z0-9_-]`, because the source becomes a directory name.

```powershell
npx tsx research/etl/cli.ts backup <location-id> <revision> <destination-file>
$env:ETL_STATE_NAMESPACE = "restore-drill"
npx tsx research/etl/cli.ts restore <destination-file>
npx tsx research/etl/cli.ts verify <location-id> <restored-revision>
```

Restore verifies hashes and reconstructs the report before publishing a pinned revision in the target namespace. When the report has an asset binding, the encrypted report backup embeds the exact stored bytes of the bound inventory revision with their SHA-256. Backup fails if that revision is missing or fails verification. Restore checks the embedded inventory against the binding, its byte checksum and its revision digest. It then republishes `loaded-assets/<inventory-id>/<asset-revision>.json` unchanged before publishing the report, so the restored report's bound-assets route returns that same asset revision. `latest.json` is written only when the target namespace has none. Inventory capture paths are not rewritten, because that would change the revision, and inventory capture blobs and manifests are not included; use `backup-assets` for those. Backups written before this change carry no inventory. They still restore, but the bound-assets route returns `404` until the inventory revision is restored separately. Claim IDs persist across namespaces. The full revision hash reflects restored capture paths. Set `ETL_BACKUP_DIRECTORY` on the scheduled FastAPI worker to back up published revisions to a separate mounted destination: reports go to `<dir>/<location-id>/<revision>.json` after each collection, and loaded asset revisions go to `<dir>/<location-id>/assets/<asset-revision>.json` (`backup-assets`) after each inventory publish. Both skip a destination that already exists. A failed asset backup fails that inventory cycle, which then retries after `ETL_ASSET_RETRY_SECONDS`. Weather archives are not backed up on a schedule: the service never runs `backfill`, so it has no weather snapshot ID to pass to `backup-weather`; run that command manually after a backfill. Keep the destination and key available after loss of the ingestion host.

Loaded asset revisions and historical weather captures use the same key and encrypted archive format. Asset archives include the normalized revision, its source manifests, and capture blobs. Restore rewrites capture paths for the target state namespace and recalculates the revision hash, so it can differ from the archived revision; the restored revision becomes `latest`. Weather archives include the backfill and its capture bytes; restore replays the original capture before publishing the archive. Keep backup files on storage separate from the ETL state directory, and keep `ETL_BACKUP_KEY` separate from those files.

```powershell
npx tsx research/etl/cli.ts backup-assets <location-id> <asset-revision> <destination-file>
npx tsx research/etl/cli.ts restore-assets <backup-file>
npx tsx research/etl/cli.ts backup-weather <snapshot-id> <destination-file>
npx tsx research/etl/cli.ts restore-weather <backup-file>
```

## Supabase state

Collection and `load-assets` write their checksummed JSON to `research/etl-state/`
as before, and mirror the same documents into a private Supabase Storage bucket
named `etl-state` at the same paths (`reports/<location-id>.json`,
`revisions/<id>/<revision>.json`, `loaded-assets/<id>/*.json`, `blobs/<sha256>.json`).
Reads (`readReport`, `readLocationAssets`) ask the bucket first and fall back to
disk, so a deployed app with no state directory serves the published revisions.
Set `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`; without them everything stays
local and writes never fail because of Supabase. To publish an existing state
directory:

```powershell
node node_modules/tsx/dist/cli.mjs scripts/backfill-etl-supabase.ts --from research/etl-state
```

The bucket is private, so the anon key cannot read it. Updates are not streamed:
the app reads a revision per request (`Cache-Control: no-store`); a live UI would
subscribe to the same objects through a Supabase Realtime channel.

## Request layer

Every collector fetch goes through `research/etl/http.ts`. Inside one process an identical request is fetched once, per-host concurrency is bounded by `ETL_HTTP_HOST_CONCURRENCY` (default `4`), retryable failures back off from `ETL_HTTP_RETRY_BASE_MS` (default `300`) up to `ETL_HTTP_RETRY_ATTEMPTS` (default `3`) and honour `Retry-After`, and a provider `304` reuses the bytes already captured. This state is process-local; see "Shared dedupe" for the cross-process layer.

Request starts to one host can be spaced by a minimum interval. `ETL_HTTP_HOST_MIN_INTERVAL_MS` is either a JSON object (`{"oasis.caiso.com":6000}`) or a `host=ms,host=ms` list, and it replaces the default map, `oasis.caiso.com=6000` (OASIS throttles anonymous callers by request rate). Other hosts are unspaced. A malformed value falls back to the default. Spacing also applies to retries, and identical in-flight requests share one start.

The validator cache that backs `304` reuse is capped by total body bytes, not entry count: `ETL_HTTP_CACHE_MAX_BYTES` (default 64 MiB) evicts least recently used entries first. Redirects fail closed by default; a feed opts in with `redirect: { follow: true, allowOrigins: [...] }`, which follows only HTTPS `Location` headers to the listed origins. Retries classify network failures by error name and `cause.code` rather than message text: `TimeoutError`, an `AbortError` raised by the layer's own timeout, undici's `TypeError`, and socket/DNS codes such as `ENOTFOUND`, `EAI_AGAIN`, `ECONNRESET`, `ECONNREFUSED`, `ETIMEDOUT` and `UND_ERR_*`.

### Shared dedupe

When `REDIS_URL` (`redis://` only; `rediss://` is not supported by this client) is set, every CLI command installs `shared-dedupe.ts` under the request layer at startup. It also needs `ETL_HTTP_SHARED_HMAC_KEY`: a secret of at least 32 bytes, given as hex or base64, shared by every process that uses the same Redis. Each stored record carries an HMAC-SHA256 over the whole record and its request key. Readers check it in constant time before anything else, so a process that can write to Redis but does not have the key cannot inject a response that is served as a capture. If `REDIS_URL` is set but the key is missing or invalid, shared dedupe stays off, and one `Mapergy: shared HTTP dedupe disabled (...)` warning (which never includes the key) goes to stderr. An unusable `REDIS_URL` prints one `Mapergy: shared HTTP dedupe disabled (...)` line to stderr and the command continues with process-local dedupe. Per normalized request key (`sha256(href, accept)`): a stored response whose HMAC, body checksum and metadata digest verify is served without touching the upstream; otherwise the process that wins `SET etl:lease:<k> NX PX <lease>` fetches, stores bytes, status and headers under `etl:resp:<k>` with a short TTL if they fit the size cap, and releases its lease; everyone else polls with backoff until the response appears, the lease disappears or the lease TTL elapses, then fetches itself. `ETL_HTTP_SHARED_LEASE_MS` (default `30000`), `ETL_HTTP_SHARED_TTL_MS` (default `30000`) and `ETL_HTTP_SHARED_MAX_BYTES` (default 1 MiB) tune it. Waiting is bounded by the lease TTL plus one command timeout, any Redis error degrades to a direct fetch, and a corrupted or unsigned stored body is never served; it counts as rejected and the leader refetches. Release is GET-then-DEL without Lua, so a re-acquired lease can be deleted early; the cost is one extra upstream fetch, never a wrong body. Tests run the protocol against an in-test RESP2 server; it has never been exercised against a real Redis.

## CAISO feeds

`research/etl/caiso.ts` implements the five-minute Today's Outlook demand and supply CSVs with header-name column matching, system-wide scope in every caveat, and an operating date derived from the capture instant in `America/Los_Angeles`. The feeds are only added when a query opts in with `caiso: true` (CLI `--caiso`, service `"caiso": true`). CAISO values are system-wide telemetry for the CAISO balancing area, not local demand, local generation mix, or local price for the study location. Updates are source-paced: CAISO every 5 minutes, NWS every 10 minutes, EIA hourly, and asset inventory daily; collecting more often reuses the last capture. Captures use the `csv.table` snapshot parser, which types cells by a strict rule so `/rows/<i>/<j>` claim locators resolve to the claimed values; `caiso.test.ts` builds a `--caiso` report from real CAISO fixture files and asserts it passes evidence verification. Supply columns are matched by published header name, and a capture whose recognized supply columns fall below a threshold fails closed. The reported row is the newest in which every value column present (`Current demand`; every recognized supply column in the header) is numeric, so a partly published supply row never stands in for the full mix; a non-empty non-numeric value cell (such as `24,031`) in a newer row fails the capture closed. `Net demand` is not a column of `demand.csv` and is not mapped. The file has no date column: a row label up to 10 minutes after the snapshot's `retrieved_at` (stamped before the request is sent) is read as the same Pacific day, and a later label as the previous day.

`load-assets` records clipped in-radius mileage per line feature and per dataset (total, by voltage band, and inside/crossing/outside counts) using `research/etl/geometry.ts`, while keeping the provider geometry unmodified for citation.

## CAISO OASIS nodal prices

`research/etl/oasis.ts` adds two anonymous OASIS `SingleZip` feeds when a query names a node (`--oasis-node`): `PRC_INTVL_LMP` v3 (market RTM, five-minute real-time intervals) and `PRC_LMP` v12 (market DAM, hourly day-ahead). The query window is built from the capture instant and the exact URL is stored on the snapshot, so replay never re-derives it from the clock. RTM queries the last full UTC hour before capture (08:37Z queries 07:00Z to 08:00Z) and reports the newest interval with a numeric LMP; every returned interval must start inside the window of the stored request URL, otherwise the capture fails closed. `feed.url` is a window-less template; only the capture-time URL is requested and stored. DAM queries the Pacific operating day containing the capture and reports the hour containing the capture instant (start <= capture < end); a capture outside every returned interval fails closed. Values are $/MWh for the LMP and its energy, congestion and loss components (`LMP`, `MCE`, `MCC`, `MCL`). CAISO names the DAM price column `MW` even though it holds $/MWh; columns are matched by header name and the other market's price column must be absent. Rows for another node or market fail the capture closed instead of being filtered, and an OASIS XML error report becomes a rejected capture. A nodal LMP is a wholesale price at one pricing node. It is not system demand, not a retail tariff, and not the price at the analysis location. Node IDs must match `^[A-Z0-9_\-.]{3,64}$`. RTM is refreshed at most every 900 seconds and DAM every 3,600 seconds.

## EIA hourly time basis and EIA-930 bulk backfill

EIA API `frequency=hourly` periods (`YYYY-MM-DDTHH`) are UTC and hour-ending: the route metadata labels the frequency "hourly (UTC)", and CISO demand for period `2026-11-14T08` equals the EIA-930 bulk row whose "UTC Time at End of Hour" is 11/14/2026 8:00 AM (both 22,227 MW). Local time is a separate `local-hourly` frequency. Invalid and local-time periods are rejected, so EIA observation age is computed on a UTC basis. The fuel feed reports the newest period that has a numeric value for every fuel the response reports for the respondent in any period; a period with a blank or not-yet-published fuel is skipped for an older complete one, and with no complete period the capture is rejected. A fuel that stops being published therefore rejects captures until its older rows leave the 200-row response window.

`backfill eia930 <respondent> <file> [--url <source-url>]` is an opt-in backfill over a locally downloaded six-month `EIA930_BALANCE_<year>_<half>.csv`. It is not part of the five-minute telemetry loop: the server answered a `Range` request with `200` and the whole ~36 MB body (no `206`, no `Accept-Ranges`), and rows are sorted by balancing authority and then time, so no bounded byte range can address the latest hour. The command stores the bytes content-addressed with a snapshot record (`--url` records where they came from; otherwise `local-file:<name>`), parses rows on "UTC Time at End of Hour" with the API-compatible `period` label, and writes `eia930/<snapshot>-<respondent>.json` under the state root. The newest hours of each authority are published with blank demand; those rows are skipped and counted, never zero-filled. A file without demand for the respondent is quarantined. The respondent must be 2 to 8 upper-case letters or digits.

## HIFLD transmission radius query

HIFLD `Transmission_Lines` is stored in a US-feet state plane (wkid 102659 / latestWkid 2237), and the server applies a `distance` in that unit: a 100-mile distance selected lines up to about 328 miles away (about 3.28 times too large; 1,784 lines instead of 694 at Westminster). The transmission count feed and its asset index therefore send no `distance` or `units`. They send a 64-vertex clockwise WGS84 polygon from `geometry.ts` `studyRing` (`geometryType=esriGeometryPolygon`, `inSR=4326`, `spatialRel=esriSpatialRelIntersects`) whose vertices are placed on great circles (spherical direct formula, the same Earth radius as `greatCircleMiles`) and widened until every straight lon/lat edge stays at least 1 m beyond the radius, so no line within the great-circle radius is excluded by the polygon. The polygon can admit a line up to about 0.13% of the radius outside the circle at 100 miles (at most about 0.16% plus 15 m across the latitudes and radii tested). `clipLine` still measures inside-radius mileage in its local tangent plane, whose circle differs from the great-circle one by up to about +/-0.33% at Westminster, so a fetched line can clip to zero miles and a line `clipLine` would keep just beyond the true radius at some bearings is not fetched. The ring is rounded to 4 decimals so the GET URL stays under ArcGIS Online's 2,048-character query limit. The point layers (substations, EIA Atlas plants) keep the point-plus-distance query. A count response that also carries an `error` key is rejected, whatever its `count`. Details and the live proof are in `docs/HIFLD-LIVE-CAPTURE.md`.

`load-assets` publishes `field_notes` per dataset describing how provider values become normalized properties, plus a note for each normalized field the layer does not publish at all, which is always `null` (HIFLD substations publish no owner or operator column). HIFLD substation names of the form `<TYPE><ID>` (UNKNOWN, TAP, RISER, DEADEND followed by an ID) become `null`, `-999999` voltage sentinels become `null`, and TAP, RISER and DEAD END records are kept with their `type`. A transmission line's `study_clip.voltage_band` is `dc` when `VOLT_CLASS` is DC or `TYPE` begins with DC, otherwise the AC band of `voltage_kv`; the layer marks DC inconsistently, so either field is enough.

`crosswalk-candidates <osm.geojson> <hifld-substations-manifest> [--max-metres N]` (default 300 m) replays the HIFLD manifest offline and pairs each OSM substation with every HIFLD point within the distance, ranked by great-circle distance, with name-similarity and voltage hints. It writes `crosswalk/<inventory-id>/candidates-<revision>.json` and `.csv` and prints their paths, revision and stats. Every row is `review.status: "unreviewed"`; the audit ignores unreviewed rows, so nothing is corroborated until a person reviews it. Absence of a candidate does not imply a missing asset in either source.

## Comparison

`compare <file>` accepts JSON containing `left`, `right`, and optional `policy` as defined in `reconcile.ts`. Provide values already normalized to equivalent scopes. The result retains candidates and distinguishes same-publisher duplicates from cross-publisher comparisons. The comparison command does not modify reports.

## Reconciliation

`reconcile <location-id> [report-revision]` runs every reviewed policy in `reconcile-policies.ts` against a stored report revision (the latest when omitted) and persists the result once per revision as a sidecar file, `reconciliations/<location-id>/<report-revision>.json` under the state root. The record is canonical JSON with an embedded digest and the `policies_version` digest of the registry, so identical inputs give identical bytes; an existing record is verified and returned unchanged, and an edited one is rejected on read. Reports themselves are never modified. Policies currently cover HIFLD vs bundled OSM substation counts, EIA Atlas vs bundled EIA-860 plant counts, EIA-930 CISO hourly demand vs CAISO five-minute demand averaged over the UTC hour, and EIA API vs EIA-930 bulk demand. Each comparison has one status: `agreement`, `within_tolerance`, `conflict` or `incomparable` (with a reason, such as a scope field that differs or an input not captured in the report). Two sides reach a value comparison only when every scope field (metric, entity, unit, interval, statistic, basis) is identical. Values are never averaged: `selected` is set only by a policy authority, or to the left side on exact agreement; a conflict without an authority keeps both candidates and selects nothing. `GET /api/location-report/<location-id>/reconciliation?report=<report-revision>` computes and persists on first request and then serves the stored record (immutable cache headers with `?report=`, `no-store` without), with `X-Report-Revision` and `X-Policies-Version`.

## Operator imports

`operator-import <envelope.json> [readings.csv]` imports one operator input. Kinds are `topology`, `equipment_rating`, `equipment_condition`, `meter_series` (readings inline or, only for this kind, from a CSV) and `quote`. The envelope must record the issuer, an ISO 8601 issue time with an explicit offset, the location and asset scope, the effective period and a visibility of `private`, `shared` or `public`. Every physical or monetary quantity is a `{ value, unit }` pair with a fixed unit per field; bare numbers, wrong units, overlapping meter intervals and duplicate asset IDs are rejected. Raw bytes are stored content-addressed under `operator/<location-id>/raw/`, the normalized record under `inputs/<revision>.json` (revision = digest of the record, so the same bytes always give the same revision), and the set of revisions under `manifests/` with a `latest.json` pointer. Records carry `method: "operator"` and are kept beside public-source records, never merged into them. Reads filter by the caller's clearance: a `public` caller sees only public inputs and a `shared` caller never sees private ones. Example envelopes for every kind are in `fixtures/operator/`.

## Line-rating regeneration

`ratings generate <weather-snapshot-id> <site-key> <year> [--utc-offset <hours>]` regenerates an hourly line-rating CSV in the columns of `public/layers/line_rating_<year>_<site>.csv` from a weather archive written by `backfill weather`. The archive is replayed against its hashed capture first, the archive center must match the site in `lib/scan/data.ts` `RATING_SITES`, and every local standard-time hour of the year must be covered. Output goes to `ratings/line_rating_<year>_<site>.csv` with a manifest recording the weather snapshot, conductor assumptions and the sha256 of the engine source. The engine is `lib/scan/rating.ts` `rateLine`. Weather is ERA5 modeled reanalysis, not station measurement, and the ratings are a screening model, not an operating rating. `ratings compare <generated.csv> <reference.csv>` reports per-column differences plus engine parity for the reference. `ratings parity <reference.csv>` runs a committed CSV's own temperature, wind and sun columns back through `rateLine` and reports per-column differences; on `line_rating_2025_westminster_hs.csv` all 8,760 rows match with a maximum absolute difference of 0 A.

## Coverage

`coverage` inventories fields in the shipped JSON artifacts, lists evidence predicates, and computes each gap from evidence on disk and in code. A gap is `{ id, title, status: "open" | "closed", evidence: [paths], reason }`, and `coverage --strict` exits 1 if and only if a gap is open. Module checks import the module and look for the named export, so a missing or failing module reads as open.

| Gap id | Closed when |
|---|---|
| `workbook-regional-regeneration` | `osm-regen.ts` exports `runOsmRegenCommand`, `eia860.ts` exports `runEia860Command`, and `docs/OSM-REGENERATION-DIFF.md` and `docs/EIA860-REGENERATION-DIFF.md` exist |
| `seed-case-field-attribution` | every record in `public/layers/niche_cases.json` and every feature in `data/nodes.json` carries a `field_sources` map whose keys cover all of its other leaf field paths |
| `hourly-weather-csv-regeneration` | `ratings.ts` exports `generateRatings` and `engineParity`, and `ratings.test.ts` calls `engineParity` |
| `operator-import` | `operator-import.ts` exports `runOperatorImportCommand` and `importOperatorInput` |
| `simulator-input-inventory` | every JSON file imported by `lib/region.ts`, `lib/grid.ts` and `lib/physics/*.ts` is in the coverage inventory, and `data/nodes.json` features carry complete `field_sources` maps |
| `provider-reconciliation` | `reconcile-report.ts` exports `reconcileReport` and `RECONCILE_POLICIES` has at least one policy |

The `field_sources` convention is defined by this check; no shipped record uses it yet, so the attribution and simulator-inventory gaps are open. The working location adapter set covers Census, one NWS station, NWS active alerts, EIA Atlas plant counts, HIFLD counts, optional hourly EIA demand and fuel, optional CAISO system feeds and optional OASIS nodal prices.
